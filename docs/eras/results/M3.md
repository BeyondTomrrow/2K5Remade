## What was built

* `src/nfl2k5_eras.h`, `src/nfl2k5_eras.c`: league state.
  * Reads `data\eras\runtime\1980\teams.csv` and `schedule.csv`, relative to the working
    directory. The header is checked. An unknown team id in the schedule refuses the package.
  * The save is under `xbox_user_path("eras\\league1\\...")`:
    * `league.ini`: format 1, season, package, user_team, created and
      `rosters = unverified community roster`. Unknown keys are kept on rewrite, and the file
      is written through `.tmp` + rename.
    * `results.csv`: the header `game_id,home_pts,away_pts,final_period,end_state,status`,
      in the format M1's capture appends.
    * `box\` and `eras.log`.
  * Reads and existence checks use a path builder that **creates nothing**
    (`league_path_peek`). Folders are created only by create, write and log. Opening the hub
    in a fresh profile leaves no `eras\` folder.
  * Format check: a missing format, or one newer than 1, is refused with a message.
  * A `user_team` id that is not in `teams.csv` is refused with `NFL2K5_ERAS_BAD_TEAM` (-5).
    It logs `league.ini user_team '<id>' is not a team of ...; league refused`, and the hub
    reads "Continue League: Unknown saved team". It no longer falls back to watch mode
    without a word.
  * New League over an existing league moves the old folder to
    `league1-replaced-<yyyymmdd-hhmmss>`. Nothing is ever deleted.
  * Next fixture: the user team's next unplayed game, else the next in schedule order.
  * Standings come from `results.csv`. Rows with status `final` or `committed` count, and
    for each game id the first line wins. Division order is "wins, fewer losses, point
    difference, points for, nickname". This is a display rule, not the 1980 tiebreak
    procedure.
* `src/nfl2k5_eras_menu.c`: the screens, served at `0xFEE00000`.
  * Addresses: event actions at `+screen*0x1000+slot*4`, row functions at
    `+screen*0x1000+0x800+row*0x40+k*4` (k 0-6 value row, 7 type-9 action, 8 row update).
    `nfl2k5_eras_menu_lookup()` dispatches through a TLS called-address.
  * It has its own 256 KB guest heap (41 KB used). Every header has its own event table or
    none, never the template's. Entry points keep EBX/ESI/EDI/EBP and `ret` with
    `g_esp += 4`.
  * **Main Menu:** "My NFL Eras" is inserted **after The Crib**, giving 8 rows: Quick Game,
    Game Modes, The Crib, My NFL Eras, Features, Options, Xbox Live, Extras.
  * **Hub** (Features template):
    * Continue League (type 9): hidden without `league.ini`; shows the refusal message.
    * New League (1980) (type 9). Over an existing league the first A only relabels the row
      to "Replace league? Press A again"; the second A replaces the league. The ask is
      cleared whenever the hub is shown again.
    * A roster label row.
  * **League** (Features template):
    * "Play Next Game: <AWAY> at <HOME> (Week n)" (type 9). In M3 it only relabels to
      "coming in the next update".
    * "Your Team: <x>", Schedule, AFC Standings, NFC Standings and a roster label row.
    * msg 3 rewrites the labels and the title ("1980 Season - Week n").
  * **Your Team** (Game Options template, no event table): None (watch CPU vs CPU) plus the
    28 franchises. The choice is written to `league.ini` at once and refused after the first
    result.
  * **Schedule:**
    * A Week 1-16 value row.
    * Game rows "AWAY at HOME", with "-" or "away - home" as the value.
    * The labels are rewritten live when the week changes.
  * **AFC / NFC Standings:**
    * 3 division header rows, with the value "W-L-T  PF-PA".
    * 14 team rows ("W-L-T  PF-PA").
    * A last row, "Rosters: unverified community / Unofficial order".
  * `NFL2K5_ERAS_MENU=main|main-scroll|modes|off` (default `main`) applies **only to the clean
    game**. Under a mod pack the Eras menu is always off and the variable is ignored (log:
    `menu: off (mod pack, NFL2K5_ERAS_MENU ignored)`). A pack's XBE may lay out
    `MAIN_MENU`, `GAME_MODES` and the templates differently, and the served functions cannot
    be reached from interpreted pack code.
* `src/recomp_manual.c`: the `0xFEE00000` range goes to `nfl2k5_eras_menu_lookup`.
* `src/main.c`: `nfl2k5_eras_menu_install(retail)` is called right after
  `nfl2k5_video_menu_install()`.
* `config/game.cmake`: adds `src/nfl2k5_eras.c` and `src/nfl2k5_eras_menu.c`.
* `tools/drive-menu.ps1`: `-Retail` passes `--retail` and skips `mods\active-pack.ini`.
* `tools/eras-capture-test.ps1`:
  * `-NoCapture`.
  * `-AppData <dir>`: LOCALAPPDATA for the game, a sandbox user folder.
  * `-SetEnv 'NAME=value',...`.

Gen patches: none. Build: `tools/build.ps1 -Game` exits 0, with no ` error` in
`logs/build-Release.log` (final build 02:16:27, round 2; the m3h-m3j tests ran on 01:48:42,
and the round-2 change is only the label-row branch in `row_action`).

Every league save made by the tests is in a sandbox user folder: `logs/eras/m3-home*`,
`m3f-home`, `m3i-home`, `m3j-home`, each holding ini files and a shader cache copied from an
earlier sandbox. The real `%LOCALAPPDATA%\NFL2K5-PC` and `saves/` were not written.

**Correction to the first report.** The first report said "Game Options' msg 1 sets
0xAA26B0", and the review answered that it is set at msg 5 (leave). What was actually
observed: with Game Options open, more than 10 s after entering and before leaving, the flag
is **1** (`m3g-dirty-in-gameoptions.bin`, `m3h-dirty-in-gameoptions.bin`). So it is set while
the screen is open, not when it is left. The earlier `m3b-dirty-in-gameoptions.bin` = 0 was
most likely a dump written before entry (the dump refreshes only every 10 s). Which message
sets it was not traced. T3.4 does not rely on it: it shows the flag is 0 after the Eras
screens, and that the prompt appears only through Game Options, as in retail.

These are recorded in the `PHASE2-PLAN.md` M3 note.

* There are no help bars (header `+0x0C` = 0):

  * The standings note is the last row.
  * The hub and League screens carry a "Rosters: unverified community roster" row.

## Engine facts learned (for M4 and the office)

* The Main Menu (`main_menu_sub`, flags `0x02`) shows 7 rows and **scrolls** to an 8th
  without the `0x04` flag. Retail Extras stays reachable at the bottom.
* The celebrity-phone icon is drawn beside the **third visible row slot**:
  * With Eras after The Crib, it is beside The Crib whenever the list is not scrolled.
  * When the list is scrolled (cursor on Extras) it sits beside "My NFL Eras", the row
    then in slot 3 (`m3h-m5.png`).
  * Retail never scrolls, so this cannot be matched in every scroll state with 8 rows. See
    known defects.
* Settings-list rows (handler `0xF3FC0`):
  * Item `+8 = 1` hides the row.
  * A row whose max equals its min draws **no value**.
  * Greyed rows (`+0xC = 1`) draw their label invisibly on the light row background.
  * A value wider than about 250 px blanks the value column.
* Label buffers rewritten in place update live.
* The Main Menu goes to the attract loop after about 30 s idle. Start returns to it, with
  the cursor reset to Quick Game.
* The press file sometimes merges or doubles a step, so check the frame after each step.
* `NFL2K5_MEMDUMP` files refresh every 10 s. Wait at least 10 s before copying one.

## Known defects / open items

* **Blocking:** the office hub of `ERAS-OFFICE-DESIGN.md` is not built; M3 is partial until
  it is, or until the orchestrator / user ratifies the proposed M3-office split.
* "Play Next Game" does nothing but relabel (M4).
* The phone icon sits beside "My NFL Eras" while the Main Menu list is scrolled down to
  Extras. This is cosmetic: only the icon's position is wrong, and the call itself is
  unaffected. It can mislead a user into pressing Eras to answer the call. Kept as a known
  defect (round 2): the draw routine that places the phone by visible slot was not traced.
  It only shows while a Crib call is pending (in m3k, scrolled with no call pending, no phone
  is drawn: `m3k-extback.png`).
* The standings order is unofficial, as stated on screen. At 0-0 it is alphabetical by
  nickname.
* The Your Team lock after the first game was not exercised, because no results exist yet
  (M4).
* `tools/drive-menu.ps1 -Retail` was parse-checked, not run. It screenshots with
  `capscreen.ps1`, which needs the window on screen, so the tests used
  `tools/eras-capture-test.ps1` (background mode).
* The test frame folders `logs/eras/m3?-frames` are large, about 4.6 GB in all. They can be
  deleted, because the PNGs named above are the evidence.
