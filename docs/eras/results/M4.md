## What was built

* **`src/nfl2k5_eras_launch.c` / `.h` (new): "Play Next Game".**
  It is called from the League row's type-9 action with `ecx` = FSM. Steps:
  1. **Refuse** when USER1/USER2 holds a Create-a-Team team. The check
     (`nfl2k5_teams_stage_check`) touches nothing. The row then reads "Can't play:
     Create-a-Team in USER1", and `eras.log` gets a line.
  2. **Snapshot** the 0x2E0 settings block `0xE5FF80..0xE60260`, `0xE5FE64..0xE5FE7C`
     (stadium, home, away, last home, last away, both playbooks), `0xE60210/14` and the
     side words `0xE5FE88 + port*0x1C` for ports 0-7.
  3. **Stage** home into side 0 (USER1) and away into side 1 (USER2) with
     `nfl2k5_teams_stage` (M2). If staging fails, both slots are released and the
     snapshot is restored.
  4. **Mode:** `[0xE5FF80] = 4`, `[0xE5FFE4] = 0`.
  5. **Ports:** `sub_00077200(port, side)`. The port that pressed A is found with
     `sub_000F3580(fsm)` (Team Select's own way). It gets 1 when the league's user team is
     at home and 2 when away. Every other port, and all ports in watch mode, get 0.
  6. **Teams through Franchise's setters** (not set_home): `sub_00077AE0(home)`,
     `sub_00077B20(away)`, `sub_00077470(stadium)`, and the uniform slots
     `sub_000E3000` / `sub_000E30E0` from team `+0x192`.
  7. **Arm and push:** arm the M1 capture (box path `box\<game_id>.json`, the league's
     `results.csv`, `roster_source = "unverified community roster"`), write
     `launched = <game_id>` to `league.ini`, then `sub_0034CA40` and push `0x55D088`.
* **Era home stadium.**
  * `teams.csv` has new columns: `stadium`, `stadium_match`, `stadium_historical`.
    `build/eras/make_runtime_package.py` writes them from
    `data/eras/league/stadiums_1966_2025.json`: the spell covering 1980, its `ingame`
    name. `--check` verifies them, and `PROVENANCE.txt` lists the mapping (9 exact, 19
    stand-ins).
  * At launch, `nfl2k5_teams_stadium_find(name)` looks up the stadium **by name** among
    the roster's stadium records:
    * count `[root+0x10]`;
    * 0x80-byte records from `[root+0x14]`;
    * name pointer at `+0x00` (the mod tools' ROST layout);
    * id at `+0x7C`.
  * The match is case-insensitive and ignores trailing spaces. The record goes into the
    home slot's `+0x114` and `[0xE5FE64]`. If the name is not found, the template's
    stadium is kept and a line is logged.
  * The other runtime files are byte-identical after the regeneration (only `teams.csv`
    and `PROVENANCE.txt` changed). T0.1 still passes.
* **Clean-up** (`nfl2k5_eras_after_game`): idempotent, keyed on an in-process "active" flag.
  1. **Commit.** If the capture status is FINAL for this game id, wait up to 3 s for the

     written". If ABANDONED, log "abandoned ... the fixture stays unplayed". If ARMED
     (backed out of Coach Match Up), disarm and log.
  2. Release both slots, restore the snapshot, clear `launched` in `league.ini`, and

### 2. The halftime hang (major)

**Diagnostic.** Gen patches `WALK_DIAG_ENTER` / `WALK_DIAG_STEP`
(`tools/apply-gen-patches.py`; applied to `src/recomp/gen/recomp_0002.c` `sub_000561F0`).
* On, they record each call's `ecx`, `edx`, `esi` and `esp` per thread.
* A walk that passes 4M entries is logged once (`[WALK]` lines) with:
  * the arguments, the caller and `[esi+8]`;
  * 24 stack words;
  * the entries the function walks (type, size, id);
  * the `esi` block.
* The diagnostic is off unless `NFL2K5_WALK_DIAG=1` (read in `src/main.c`). Off, the cost is
  one load and a branch per entry.
* The code is in `src/nfl2k5_eras_launch.c`.

**Runs** (all with `NFL2K5_WALK_DIAG=1`):

| run | games in one process | halftimes passed | Team Comparison segments | `[WALK]` | halftime STALL | failed cache opens |
|---|---|---|---|---|---|---|
| m4r1 | 1 Quick Game (1998 Vikings in USER1), then **4 Eras games back to back** (49ers-Saints, Oilers-Steelers, Colts-Jets, Broncos-Eagles; all committed, 3 in OT) | 5 | 6 | 0 | 0 | 0 |
| m4r2 (control) | 3 retail Quick Games (a 4th was aborted by the driver in the menus) | 3 | 2 | 0 | 0 | 0 |
| m4r3 (control) | 3 retail Quick Games back to back | 3 | 1 | 0 | 0 | 0 |

The only `[GGL]` line in these runs is the usual boot-time "held the guest CPU ... 0x00420A77"
line, which every run since m4a has.

**What sets m4c apart.** The m4c log has 82,774 failed file opens with
`ERROR_SHARING_VIOLATION`:
* 82,763 on `saves\Cache\tr000000.iff`, the game's rolling transient cache;
* 11 on `original\disc\CACHE\LocalCache08.bin`, from boot.

The failures start right after the launch of the second Eras game (line 6374), about 5,000
per 5,000 log lines, and run until line 92,492. The halftime "Team Comparison" segment shows
at 93,275, and the STALL is at 93,279.

Every other run has 0 such failures: m4a, m4b, m4e, m4f, m4r1, m4r2 and m4r3. So during m4c
another process held the game's cache files. The disc cache was held from boot, so this was
most likely a second NFL2K5 instance; both share `saves\` and `original\`.
`sub_000561F0` walks a resource's entries by size. A resource whose cache read failed would
give it zero-size entries, and it would never end.

**Conclusion.**
* No Eras-specific cause was found.
* 11 Eras halftimes have passed:
  * 7 in m4a-m4f (the `period 2 -> 3` lines), besides the one hang;
  * 4 back to back in m4r1, with the diagnostic on.
* 7 retail halftimes passed as a control.
* The one hang happened in the only run with the cache files held by another process.

This makes an environmental cause the leading explanation, but it is **not proven**. The
hang was not reproduced, so the `[WALK]` dump of the walk was never taken.

The stale spare-pool name pointers named in the review were not changed. Those records point
into the per-side arena, and every arena string is valid memory, so they could change a name
but could not make this walk loop. Nothing points at them causing the hang.

**Next step if it recurs:** run with `NFL2K5_WALK_DIAG=1`. The `[WALK]` lines give the
resource and the caller.

A test that holds `tr000000.iff` open during a retail Quick Game would show whether the
cache failure alone reproduces the hang. It was not run, because it means locking a file
under `saves\`.

### 3. The settings-block rollback (minor 5)

**Code.** Before the restore, `block_diff()` logs every byte range of `0xE5FF80..0xE60260`
that differs from the snapshot.

**m4r1, four Eras games.** The only ranges were these:
* `0xE5FFA4` temperature, `0xE60088` (the time-of-day value that `sub_000E2DB0` writes),
  `0xE600C0` wind, and `0xE60184` resolved time of day. These are per-game outputs that Start
  Game recomputes from the user's Time of Day / Weather settings every game
  (`MATCH-LAUNCH.md` table: `sub_000E3150` / `sub_000E3350`; `sub_00134140` and
  `sub_0011AD00` copy the same group). `0xE5FFAC` precipitation and `0xE600C4` belong to the
  same group but did not change in these games.
* `0xE60210` / `0xE60214`, the uniform slots, which the launch itself sets.

For example, game 1:
`00E5FFA4..00E5FFA6 (428030B6 -> 42868BB2) 00E60088..00E60089 (00003A98 -> 00005E8D) 00E600C0..00E600C2 (42F9A646 -> 42C52ECF) 00E60184..00E60184 (00000001 -> 00000002) 00E60210 (4 -> 0) 00E60214 (3 -> 0)`.

So no user-facing option, counter or Crib field in the block is written by the match or End
Of Game. Restoring the whole block is verified safe for these games. Mode and First Person
Football did not differ, because the snapshot was taken after a Quick Game, which is also
mode 4.

A change made in Coach Match Up "Options" during an Eras game would show up in the same log
line and is still rolled back (documented, risk 7).
