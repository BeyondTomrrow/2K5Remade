in background mode (`RECOMP_BACKGROUND=1`, `RECOMP_AUDIO_MUTE=1`, `NFL2K5_NO_HOST_PAD=always`,
`NFL2K5_RENDER_SCALE=1`), CPU vs CPU, with the M1 capture on (`NFL2K5_ERAS_CAPTURE=1`,
`NFL2K5_ERAS_LOG=1`), `NFL2K5_QUARTER_SECONDS=60`, `NFL2K5_TEAMS_LOG=1` and

## What was built

* `src/nfl2k5_teams.h` (new): the staging API, the arena layout macros, and the error codes.
* `src/nfl2k5_teams.c`:
  * `int nfl2k5_teams_stage(side, template_entry, roster_csv, city, nickname, abbr)`. It uses
    `spare_slot(side)` (side 0 is USER1/home, side 1 is USER2/away). It refuses with
    `NFL2K5_STAGE_USER_TEAM` (-3), touching nothing, when the slot holds a user-created team
    (category 2 with players, the `slot_usable` test). It checks the template index and that the
    CSV exists, then calls `load_historic`. It writes city `+0x138`, nickname `+0x104` and
    abbreviation `+0x108` as arena strings, then runs the roster writer. If the row count differs
    from the team's player count, it releases the slot and returns `NFL2K5_STAGE_ROSTER_CSV`.
    It saves and restores every guest register and the lazy flags.
    `nfl2k5_teams_stage_message(code)` returns help-bar text for each code.
  * `nfl2k5_teams_release(side)` wraps `release_slot`, and only acts on a category-4 (staged)
    slot. `nfl2k5_teams_staged_slot(side)` returns the staged slot.
  * Special-teams roles `+0x194..+0x199` (holder, KR1, KR2, K, LS, PR; meanings from the mod
    tools). T2.1 showed the templates' values point at the wrong players, so a role is now set
    again whenever its player's new position cannot fill it:
    * holder: the first P, otherwise the second QB;
    * K: the first K, otherwise P;
    * LS: the last C;
    * KR1/KR2/PR: the fastest backup at a returner position.

    Roles that are still valid are kept and logged as `(ok)`. `NFL2K5_ERAS_ST_FIX=0` turns the
    fix off and only logs.
  * `nfl2k5_teams_identity_check(side, match_team)` (T2.2). It is called by the M1 capture at the
    final whistle and does nothing unless that side was staged.
  * Test trigger `NFL2K5_ERAS_STAGE_TEST=<home_id>,<away_id>`:
    * The first Team Select step reads `data\eras\runtime\1980\teams.csv`, stages both sides and
      publishes both.
    * Later steps re-publish the staged team.
    * When the front-end FSM pops back to the Main Menu (`0x515660`), both slots are released.
      Any of `[0xE5FE68/6C/70/74]` still pointing at a released slot gets its value from before
      the staging back (55D088's msg 2 had restored 68/6C to the slots).
* `src/nfl2k5_team_files.c`:
  * `nfl2k5_team_roster` is now a path wrapper (roster.csv beside team.rost, plus the oldschool
    dress) around the new `int nfl2k5_team_roster_file(path, slot, arena)`. That function returns
    the rows written, or -1.
  * With an arena, names go into fixed slots. With arena 0, added teams keep the old behaviour
    and get new strings.
  * `nfl2k5_team_arena(side)` allocates once per side with `xbox_HeapAlloc`: 64 rows x
    {first, last} x 32 UTF-16 characters, plus city, nickname and abbreviation (8,384 bytes).
    Every staging rewrites it, so nothing leaks per game. Names are cut at 31 characters.
  * Birth dates are not written (plan: known defect, so in-game ages mean nothing).
* `src/nfl2k5_eras_capture.c`: calls `nfl2k5_teams_identity_check` for both sides after reading
  them at the whistle.
* `src/main.c` `nfl2k5_diag_fsm`: on a pop, calls `nfl2k5_teams_fsm_pop(obj, new_top)`. This is
  the test trigger's release point. That hook runs with the guest registers in their globals
  (gen-locals `RECOMP_REGS_OUT`), and the release saves and restores them.
* `tools/eras-capture-test.ps1`: a `-Stage <home>,<away>` switch sets `NFL2K5_ERAS_STAGE_TEST`
  and `NFL2K5_TEAMS_LOG`.
* `build/eras/m2_identity_check.py` (new): the offline half of T2.2. It compares the box JSON
  players with the CSV rows (names, jersey, position) and checks the name pointers against the
  arena layout logged at staging.
* There are no gen patches, as planned. Build: `tools/build.ps1 -Game` exits 0 and
  `logs/build-Release.log` has no ` error`.

## Known defects and notes for M3/M4

* There is no in-game test of the refusal path (`NFL2K5_STAGE_USER_TEAM`): no Create-a-Team team
  was in USER1/USER2, and saves/ must not be edited by hand. The check runs before anything is
  touched, and the code is the `slot_usable` test.
* LS (`+0x198`) read 0 for all four templates (player 0, a CB). It is not proven that 0 means
  "LS player index 0" rather than "unused". Setting it to the last C is harmless either way.
* Team Select background art still shows the previous team's watermark, and the Raiders template
  reads "CURRENT UNIFORM". Both are cosmetic; the retail screens do the same for historic teams.
* Coaches, playbook label, stadium and uniforms come from the template. The Colts play in the
  template stadium (an indoor dome) in 1980. That is outside M2's scope.
* Roster content is the unverified community roster. For example, the 1980 Raiders list Stabler
  first and the Oilers list Pastorini, although the two were traded for each other before the
  1980 season. This is data, not staging.
* M4: call `nfl2k5_teams_stage(0, home...)` / `(1, away...)` and `nfl2k5_teams_release(0/1)`. The
  stage function preserves the guest registers. The test trigger's Main Menu release and global
  restore are test-only, and M4 should do its own snapshot and restore. The capture JSON's
  game_id numbering in the test switch counts the attract demo (this game was `test-3`).
* The `src/nfl2k5_team_files.c` working copy now has LF line endings (git normalises them anyway).
