# Custom soundtracks / Crib Jukebox: investigation and fix (2026-10-21)

User report: "I cannot play my playlist or songs on base or softdrink if i open it in crib it
just goes back and plays menu music not even the songs I included".

## Summary

| Case | Result |

| Base game, menus (Options > Presentation > Crib Music = **Crib/Menus**, the user's setting) | **Works.** The playlist takes over the menu music as soon as the Main Menu opens. |

Fixed by the SOFTDRINK v0.6.1 boot work (commit af2d038). Its music code (`0x014DF850`-`0x014DFEBE`) is byte-identical to v0.6. |

## SOFTDRINK boot crash with custom soundtracks: root cause

Seen in every SOFTDRINK v0.6 run with soundtracks (`logs\music\s1/s2/s7`, and before this
work in `logs\sd2`, `sd3`, `sdm4`, `sdz`, `eras\m10-mm-softdrink`); a run with an empty
`Music\` and no `ST.DB` (`n1`) booted.

```
[CRASH] exception=0xC0000094 ... function=sub_003CAD50+0xDF
  [1] sub_00245480  [2] interp_execute ...
```

SOFTDRINK starts its own front-end music in pack code at `0x014DF9C5` (interpreted): it loads a
retail AUSB bank (`femusic`/`cribmusic`), builds a song entry with `sub_003CAD20` at
`[esp+10h]`, sets the bank on the stream player `0xC3CC10` (`sub_000CEF80`), then hands the
entry to `sub_00245480` from `[esp+10h]` again. An instruction trace
(`NFL2K5_INTERP_TRACE=14DF9C5-14DFBA5`, `logs\music\s9.stderr.log`) shows esp **01D0AAA0
before** the call to `sub_000CEF80` at `0x014DFAE7` and **01D0AAA4 after**: the lifted
`sub_000CEF80` returned 4 bytes high, so the second `lea edx,[esp+10h]` pointed 4 bytes past
the entry, `sub_00245480` read stale stack (`{070BF870, 074258A0, 01D0AEBC}`) as
`{bank, start, end}`, and `sub_003CAD50` divided by the garbage bank's `+0x48`.
On pack builds our gen patch `PACK_MENU_MUSIC_PLAYER` opens that player inside
`sub_000CEF80` (2026-10-08), which is the path that ran here. With the function interpreted
instead (`NFL2K5_INTERP_FORCE=CEE50-CEF94`) the stack came back balanced.

### Fix

`tools\apply-gen-patches.py` / `src\recomp\gen\recomp_0006.c`:

* `PACK_MENU_MUSIC_PLAYER` now restores esp after its `sub_000CF0F0` call and records the
  entry esp.
* New `PACK_MENU_MUSIC_ESP` at `loc_000CEF93` (the function's single exit): on pack builds,
  esp is set back to the entry value before `pop esi; ret` -- the function is a plain `ret`,
  so this is exact. Retail builds are untouched (`nfl2k5_pack_build` is 0).

Diagnostics added: `NFL2K5_INTERP_TRACE=lo-hi` (src\interp\x86_interp.c) prints every
interpreted instruction in that range with its registers.

## 2026-10-22: in SOFTDRINK the player's playlist wins, and R3 skip works

**Default now:** when a playable Jukebox playlist is selected, SOFTDRINK (v0.6 and v0.6.1) plays it
in the Crib and -- with Options > Presentation > Crib Music = Crib/Menus (or Crib/Menus/Game) -- in
the menus, like the base game; R3 / a finished song moves to the playlist's next song. With no
playlist (or one whose songs are gone from `Music\`), SOFTDRINK's own shuffle plays as before.

**Switch:** `nfl2k5_game.ini` (the per-user folder, `%LOCALAPPDATA%\NFL2K5-PC\`)
`pack_shuffle_first = 1` gives the pack's shuffle priority again (the key is added to the file,
set to 0, the first time a SOFTDRINK build starts). `NFL2K5_PACK_SHUFFLE_FIRST=0/1` overrides it for
one run; `NFL2K5_PACK_MUSIC_LOG=1` logs every music request. No F1/Options entry: the F1 pages are
video/controls, and the game's own Presentation page has no free row.

### What SOFTDRINK does (pack code `0x014DF850`-`0x014DFEBE`, byte-identical in v0.6 and v0.6.1)

| Retail | SOFTDRINK | Effect on a playlist |
|---|---|---|
| context rows at `0xAC9EC0`: `{Frontend, femusic}`, `{UserList, no bank}` | data: both rows are `cribmusic` banks | the UserList row (the playlist) plays a bank |
| music mode switch `0x000F6510` (0 off, 1 menus, 2 loading, 3 Crib, 4 game) | `jmp 0x014DFD71`: menus and Crib -> its Frontend shuffle | the Crib / menus never ask for the playlist |
| context switch `0x002804C0` | `jmp 0x014DFD00`: Frontend **and UserList** -> its shuffle | |
| custom song finished callback `push 0x27F040` at `0x0028016D` | `push 0x014DFBF6`: stop, restart the same entry | a song never advances; R3 skip replays the song ("when i skip a song in softdrink plays a song cant skip") |
| next song `0x0027F040` | `jmp 0x014DFE72` | |

### The fix (`src/nfl2k5_local_music.cpp`, interpreter hooks, registered only when all the pack bytes above match)

* `0x014DFD71` (mode switch): for the modes where retail asks for UserList (Crib always; menus /
  loading / game when `0xB9E298` / `0xB9E29C` / `0xB9E2A4` say so) and a playable playlist is
  selected, run the retail handler (`push esi; mov esi, ecx`, jump through `0xF65B4`).
* `0x014DFD00` (context switch) for `UserList`: run the retail routine from `0x002804C7`; the
  UserList row is put back to retail `{UserList, 0, 0, 0}` the first time.
* `0x00280507` (from `0x00280506`, the end of that routine): start the current playlist entry at
  `0x0027FF90` (the pack's `0x014DFCE4` hook there sets its own "playlist playing" flag, so its
  shuffle stays out).
* `0x014DF9C5` (the pack's shuffle start, called on every screen push/pop and when a paused
  menu resumes): when the UserList row is active with a playlist and the pack would really start
  its shuffle, resume the playlist instead.
* `0x014DFBF6` (song finished) and `0x014DFE72` (next song): for the playlist, run retail
  `0x0027F040` (from `0x0027F045`), which moves to the next entry with the game's own shuffle /
  repeat rules. R3 pulls the song's end in, so the skip now moves on too.
* "Playable playlist" = the game's list (`0xC3CBF8`, head `0xC3CBE8`) has a current entry
  (`0xC3CBFC`) whose album is a game bank (`< 0x12`) or an existing custom soundtrack
  (`album - 0x12 <` the soundtrack count in the last `ST.DB`).

## What the user needs to know

* Playlists are the folders in `<GameRoot>\Music\` (here `E:\NFL2K5-PC\Music\`): one folder =
  one soundtrack, MP3/WMA/WAV/M4A/FLAC/OGG. They are converted once into
  `saves\Soundtracks\cache` (a minute or so for new songs) and then appear in the Crib Jukebox
  and in Create Stadium Music.
* Build the playlist in the Crib Jukebox (A adds a track). To hear it outside the Crib, set
  Options > Presentation > **Crib Music** to Crib/Menus (already set in the user's save) or
  Crib/Menus/Game.
* SOFTDRINK: the playlist now wins over the pack's shuffle (Crib, and the menus with Crib/Menus);
  `pack_shuffle_first = 1` in `nfl2k5_game.ini` brings the pack's shuffle back. R3 skips to the
  playlist's next song in both games.
