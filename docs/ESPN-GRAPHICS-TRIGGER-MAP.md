# ESPN graphics trigger map

Generated by `tools/analyze-presentation-triggers.py` from runtime logs. Counts are observations, not guesses about graphic meaning.

To collect a focused trace without enabling every verbose runtime diagnostic,
launch the game with `NFL2K5_PRESENTATION_TRACE=1`. This records presentation
command starts plus the existing `[CARD]`, `[POPUPOP]`, and lineup records.
After the session, run `python tools/analyze-presentation-triggers.py` again.

## Hooked trigger families

| Native family | Runtime hook | Data captured |
|---|---|---|
| Presentation script | `DIAG_SCRIPTOP` in `sub_000DBC10` | opcode, command type, start/poll handlers, context |
| ESPN player/stat cards | `PLAYERCARD_PROBE` in `sub_002604D0` | card kind, roster pointers, native popup title |
| Generic ESPN popups | `DIAG_POPUPSHOW` in `sub_0008ACF0` | slot, timeout, title, message, callback |
| Starting lineup ticker | `LINEUP_TICKER` in `sub_000FFBA0` | offense/defense and eleven roster records |
| Scorebug visibility/layout | hooks in `sub_000FC200` / `sub_000FCE70` | native visibility and live scorebug state |
| Period boundary | broadcast state at `0x00E602C4` | quarter transition, halftime, overtime, final |

## Replacement rule

A custom broadcast package should replace an ESPN graphic only after its exact native trigger is identified. Live GameCast/roster values supply data; they do not trigger a graphic. For example, the FOX persistent QB insert stays inside FOX, while SNF player panels wait for the matching ESPN card or popup event.

Observed lineup triggers: offense 45, defense 3.
Machine-readable card table: `logs/espn-card-triggers.csv`.
